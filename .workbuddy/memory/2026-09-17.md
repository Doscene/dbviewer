**踩坑**

- `vsce package --out <dir>/<file>.vsix` 时 **`<dir>` 不存在不会自动创建**，直接 `ENOENT` 报错；需先 `New-Item -ItemType Directory -Force`。
- 打包日志里 "Files included in the VSIX:" 上方会单独打印一行输出文件名（`dbviewer-0.5.0.vsix`），**不是包内容**，别误判成旧包被塞进去了。核对方式是比体积：旧包 818 719 B、新包 819 230 B，若真含旧包应 >1.5 MB。

**改名过程（本轮最大的坑：`name` 全局唯一）**

| 尝试 | 结果 |
|---|---|
| `dbviewer` | 被拒 —— `The extension 'dbviewer' already exists in the Marketplace` |
| `db-viewer`（盖伦选） | 同样被拒 |
| `dbviewer-dsc`（盖伦定，`dsc` = doscene.cloud） | **通过** |

- 占用者**无法查证也无法预验证**：`vsce show`、`extensionquery`（含 `Unpublished`/`IncludeNameConflictInfo` 标志）、公开文本搜索全都看不到 —— 已下架扩展的名字会被市场永久保留且不可见。占用者也不是本组织历史 publisher（`srdcloud.*` / `doscene.*` 逐个查均 not found）。
- 结论：`db` 系通用词已被批量占位，直接上品牌前缀。改 `name` 不影响命令 ID / 配置项前缀 / 视图 ID，那些一律保持 `dbviewer.*` 未动。
- `scripts/activate-test.js` 从 package.json 推导扩展 id，所以改名后测试自动跟随，无硬编码漂移。

**其它踩坑**

- `vsce verify-pat doscene-cloud` **失败**（`Access Denied: ... needs the following permission(s) on the resource /doscene-cloud: View user permissions on a resource`），但**发布照常成功** —— 这个自检要求的权限级别高于发布本身，别据此判定 PAT 无效。
- `vsce package --out <dir>/<file>.vsix` 中 `<dir>` 不存在会直接 `ENOENT`，不会自动创建。
- 打包日志 "Files included in the VSIX:" 上方单独一行输出文件名，不是包内容；核对是否误含旧包要比体积（旧 818 719 B + 新 819 230 B，真含旧包该 >1.5 MB）。
- gallery 的 `publishers/<id>` 端点在当前网络对**任何** publisher 都返回 404（`ms-python` 亦然），不能当存在性判据。
- 最终选用的发布方式：`vsce publish --packagePath .tmp-vsix/dbviewer-dsc-0.5.0.vsix` —— 跳过重打包与 git 工作区检查。
