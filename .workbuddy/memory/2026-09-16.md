# 2026-09-16

## DBViewer —— VS Code 数据库客户端插件（从零开发）

**目标**：开发兼容 Windows 原生 + WSL 双环境的 VS Code 数据库插件，参照 Database Client，内置 MySQL/PostgreSQL 且驱动可扩展。

**技术栈**：TypeScript 5.6 + VS Code API ^1.90、mysql2 ^3.11、pg ^8.13。CJS 输出到 `out/`。

**核心设计决策**

1. `extensionKind: ["workspace", "ui"]` —— Remote-WSL 时扩展跑在 WSL 侧直连数据库，避免跨网络。
2. **跨环境差异全部收敛到 `src/platform/`**：环境探测、主机别名解析、路径互转、子进程通道。业务层无 `if (isWSL)` 分支。
3. 主机别名方案消除配置漂移：`__windows_host__`（WSL 中读 `/proc/net/route` 默认网关）、`__wsl_host__`（Windows 中默认 127.0.0.1，依赖 WSL2 localhost 转发）、`__localhost__`。
4. **默认不执行外部命令**：初版用 `wsl.exe hostname -I`，但本机安全策略会拦截 `wsl.exe`（冒烟测试直接被沙箱拦停），改为纯文件读取 + 可选的 `dbviewer.allowExternalCommand` 开关。
5. 驱动注册表：元数据（`definitions.ts`，无 SDK 依赖）与工厂（惰性 `require`）分离，保证"新建连接"下拉框不加载几 MB 的驱动 SDK。
6. 多语句执行：自行拆分（处理字符串/注释/PG `$$` 块）后顺序执行，每语句独立 ResultSet + 精确错误定位；`SELECT` 类自动追加 LIMIT。
7. PG 查询用 `rowMode: 'array'` + 列名去重，规避 JOIN 同名列互相覆盖丢数据。
8. `sidecar` 模式：`ProcessChannel` + `SidecarDriverProxy`，跨平台 fork 需注入 `ELECTRON_RUN_AS_NODE=1`（Windows 上 execPath 是 Code.exe）、`windowsHide`、UTF-8 编码。

**验证结果**

- `tsc -p ./` 零错误（修了 3 轮：类型收窄、参数顺序、未用变量）。
- `scripts/smoke-test.js`：28 项全过（环境探测、别名解析、路径互转、SQL 切分、序列化、驱动注册表、结果结构）。
- `scripts/activate-test.js`：27 项全过（mock `vscode` 模块后真实调用 `activate()`，校验命令注册与 package.json 声明双向一致、树视图创建、全部命令空参不抛异常、`deactivate()` 无异常）。
- `vsce package` 产出 `dbviewer-0.1.0.vsix`（308 文件 / 733.9 KB）。

**踩坑**

- `vsce package --no-dependencies` 不会打包 `node_modules`，装上去 `require('mysql2')` 必失败；必须不带该参数打包。
- **并行编辑同一文件会丢写入**：一次消息里对同一文件发两个 Edit，只有一个生效。必须一个文件一次编辑。
- Bash 工具在本机完全不可用（缺 coreutils），npm/tsc/node 一律走 PowerShell 并把输出落盘后 Read。

**后续可扩展**：SQLite / SQL Server / Oracle 驱动（实现 `IDatabaseDriver` + 注册即可）、SSL CA 证书配置、连接导入导出。

## 需求迭代（v0.3.0）：驱动图标 + 结果编辑 + 导出扩展 + SQL 回显

**用户原话**：「1、链接图标使用对应数据库类型的图表，例如mysql则是mysql图表。2、查询结果中表格支持编辑、支持导出为excel、csv、jsonl格式的文件 3、查询结果需要展示查询的sql。」

### 1. 按数据库类型显示图标

- `DriverDefinition.icon` 新增字段（`media/` 下的文件名），新增 `media/db-mysql.svg`（`#E48E00`）、`media/db-postgresql.svg`（`#336791`）。
- 连接树：`ConnectionsTreeProvider` 构造参数新增 `registry` + `extensionUri`，连接节点 `iconPath` 取 `driverIcon(profile.driver)`（文件 URI）；**改为图标表达"这是什么数据库"，状态改由 `description` 文字承担**（原方案用 `ThemeIcon('database'/'debug-disconnect')`，会丢失数据库类型信息）。
- 连接表单：`ConnectionFormHost.drivers[].icon` 传文件名，面板内 `asWebviewUri` 转 URI 后注入 bootstrap 的 `iconUri`；HTML 加 `<img id="driverIcon">`，切换驱动即时更换，无图标时 `hidden`。

### 2. 结果表格编辑（核心设计）

**链路**：Webview 双击 → 回传 `{setIndex, rowIndex(原始行下标), column, value, isNull}` → `ResultPanel.handleCellEdit()` 用扩展侧持有的原始结果取主键值 → `ConnectionManager.updateCell()` → `driver.updateCell()` 生成并执行 UPDATE → 回传 `cellUpdated` 更新前端。

**关键决策**

- **编辑能力是推导出来的，不是默认给的**。新模块 `src/core/editTarget.ts`：
  1. 驱动需 `capabilities.editable === true` 且实现了 `updateCell`；
  2. 表名来源优先级：调用方给的 `fallback`（树视图"查看数据"）> 从 SQL 的 `FROM` 子句推导；
  3. 主键**必须回源 `listColumns`**，绝不从结果列名臆断；
  4. 主键列必须全部出现在结果列中，否则拒绝（否则会改错行）；
  5. 只接单表 `SELECT`（`WITH`/`UNION`/`FROM (子查询)` 一律放弃）；`ResultPanel` 层再限制"多语句/多结果集不可编辑"。
  - `maskLiterals()` 把字符串字面量与注释替换成**等长空白**（保持下标不变），再用 `\bfrom\b` 定位，避免注释里的 `from` 或子查询被误认。双引号/反引号是标识符必须保留。
- **前端排序只改 `set.order` 排列数组，不改 `rows`**。这样回传的行下标恒等于原始行下标，扩展侧据主键定位才不会漂移。这是本轮最容易踩的坑。
- **SQL 生成 + 执行整体下放到驱动层**（`IDatabaseDriver.updateCell()`），因为标识符引用（`` ` `` / `"`）与字面量转义规则因方言而异。接口**必须是 async**——sidecar 模式下驱动在子进程，同步方法无法跨进程调用。
- 驱动内 `updateCell` 复用 `this.execute()`，只读拦截 / 超时 / 错误归一化自动生效。
- 空值语义跟随原值：原值为 `NULL` 且输入为空 → 仍写 `NULL`；原值为空串 → 保持空串。数字列按原值类型还原（`coerceValue`），否则 `int` 列会收到 `'1'`。

### 3. 导出扩展为四种格式

- 新增 `src/core/exporters.ts`（纯 Node，无 `vscode` 依赖），`serializeResult(format, fields, rows, sheetName)` 统一返回 `{data, extension, mimeType, label}`。
- **XLSX 零依赖手写**：先装了 `xlsx@0.18.5`，发现已停止维护且有 CVE-2023-30533（原型污染），立刻卸载改为自研——`zlib.deflateRawSync` + 手算 CRC32 组 ZIP 容器，工作表用 `inlineStr` 省掉 sharedStrings 与配套 rels。
- 导出对话框 `defaultUri` 里的连接名要过滤 `[\\/:*?"<>|]`，否则带 `/` 的连接名会导致保存失败。

### 4. 结果面板展示执行的 SQL

- `ResultSet.sql` 语义定为**实际下发的 SQL**（`buildResultSet({executedSql})`，MySQL 路径传 `finalSql`、PG 传 `finalSql`），而非编辑器里的原文——用户要核对的是"到底执行了什么"，含自动追加的 `LIMIT`。
- 面板顶部 `#sqlBox` 常驻展示，可折叠可复制；编辑产生的 UPDATE 追加显示在 `#editLog`。
- `ResultPanel.buildPayload()` 把 `lastEditSql` 一并回传，Webview 重载后仍能看到改了什么；`ready` 消息改为直接 `post(buildPayload())`。

### 顺手修掉的两个既有问题

1. `DriverRegistry.validate()` 的 schema 判定写反了：`if (!caps.schemas && typeof listSchemas !== 'function')` —— 意思是"不声明 schema 支持的驱动也必须实现 listSchemas()"。改为 `if (caps.schemas && ...)`，并补上 `columns` 的对应校验。
2. `scripts/smoke-test.js` 里第 6 节的异步断言用的是同步 `check()`（没有 `await`），失败会被静默吞掉。新增 `checkAsync()` 并把该节移入 async 主流程。

### 验证

- `tsc` 零错误（改完 first pass 只有 1 个 TS6133：`lastEditSql` 只写不读 → 把它接入 `buildPayload` 而非删掉）。
- 冒烟测试 28 → **47 项**；激活测试 36 → **46 项**；`npm test` 全绿。
- `dbviewer-0.3.0.vsix` 打包成功。**新增 `.vscodeignore` 规则**：`.tmp*` / `.workbuddy/**` / `scripts/**` / `*.vsix` —— 第一版打包把 `.tmp-*.log` 构建日志、`.workbuddy/`、`scripts/` 全塞进 vsix 了。
- 本机沙箱**禁止 `Remove-Item` 删除文件**（静默 exit 1，无报错输出）。临时文件只能靠 `.vscodeignore` / `.gitignore` 规避，别指望删掉。

## 需求迭代（v0.4.0）：六项调整

**用户原话**：「1、左键双击链接可以激活链接 2、查询结果中的sql可以修改并可执行 3、链接图标使用数据库厂家的官方图标 4、导出excel表格样式请调整样式风格尽量现代化 5、编辑数据项后要点击确认按钮在更新数据库中数据 6、新建的查询编辑器页面增加按钮执行sql。」

### 1. 连接节点单击即连接

- VS Code **树视图没有双击事件**，`TreeItem.command` 单击就触发。折中做法：只在 `state !== 'connected' && state !== 'connecting'` 时挂 `command = { command: 'dbviewer.connect', arguments: [item] }`；已连接节点不挂，否则单击选中会误触发连接。
- 已在 README「已知限制」里写明这条平台约束，避免后续再被当成 bug 提。

### 2. 结果面板 SQL 可改可执行

- HTML：`<pre id="sqlView">` → `<textarea id="sqlEditor">`，标题行加 `▶ 执行 / 还原` 与 `Ctrl+Enter` 提示。
- **关键坑**：`render()` 会被排序、翻页、切页频繁触发，`renderSql()` 里绝对不能回填 textarea 的 `value`，否则用户正在敲的内容会被冲掉。拆出独立的 `syncSqlEditor()`，只在「新结果到达 / 切结果集 / 点还原 / clear / error」时调用，配 `sqlDirty` 标志（`input` 时置位）。
- 执行回调 `ResultContext.executeSql` 由**命令层注入**（`runSql` 里闭包住已解析的 `resolvedId`，回调用同一函数递归），这样危险语句二次确认、超时、错误翻译全都照旧生效，也不会把结果集换到别的连接。`buildPayload` 增加 `canExecute`，无回调时 textarea 只读、执行按钮隐藏。

### 3. 单元格编辑改为「先攒、确认后落库」

- 新增 `state.pending`（key = `setIndex|rowIndex|fieldIndex`）。双击只写 pending 并重绘（`.pending` 橙色高亮 + 按钮显示计数），点「应用修改 (N)」才发 `applyEdits`；「放弃」清空。
- 重绘时**pending 值优先于行数据渲染**（用户看到的必须是自己刚输入的）；改回列中现有值则删除 pending 项。`copyCurrentPage` 也走同一套取值逻辑。
- 扩展侧 `handleCellEdit` 拆出 `applyCellEdit()`，新增 `handleCellEdits()` **逐条**提交（不拼大 UPDATE），返回 `cellsUpdated` 汇总；失败格保留 pending 并显示原因。单条 `updateCell` 路径保留，兼容旧协议与既有测试。
- CSS 补 `[hidden] { display: none !important; }`：`#editGroup` 是 `display:flex`，光有 `hidden` 属性会被组件样式盖掉。

### 4. Excel 导出现代化

- `exporters.ts` 重写：`STYLE = { plain:0, header:1, body:2, bodyAlt:3 }`；冻结首行 `<pane ySplit="1" .../>`、`<autoFilter>`、`<cols>` 按内容自适应（**CJK/全角按双宽**，夹在 9~52）、表头实心 `#2563EB` + 白字加粗、斑马纹 `#F6F8FB`、行底细线 `#E5E7EB`、`vertical="top"`。
- **`CT_Worksheet` 是 `xsd:sequence`**：`cols` 必须在 `sheetData` 之前，`autoFilter` 必须在之后，顺序错了 Excel 判文件损坏。测试里直接断言 `indexOf` 先后。
- `fills` 第 0/1 项必须是 `none`/`gray125`（ECMA-376 强制），业务填充从索引 2 起。

### 5. 官方品牌图标

- 从 devicon（jsdelivr）取 `mysql-original.svg`（海豚）、`postgresql-original.svg`（大象），`scripts/build-brand-icons.js` 归一到统一 `viewBox="0 0 128 128"`、补品牌色、**删掉 `width`/`height`**（尺寸应交由使用方 CSS 决定），文件头写商标归属。
- 脚本注释写着"丢掉 width/height"但模板仍在输出，属自相矛盾，已按注释修正。
- `definitions.ts` 早就指向 `db-mysql.svg` / `db-postgresql.svg`，所以这步只换了文件内容，UI 侧零改动。

### 6. 查询编辑器执行按钮

- `package.json` 新增 `menus."editor/title"`：`dbviewer.runQuery`（`navigation@1`）、`dbviewer.runSelection`（`navigation@2`）、`dbviewer.pickConnection`（`navigation@3`），`when: "editorLangId == sql"`；`pickConnection` 补 `icon: "$(plug)"`。`editor/context` 也补了切换连接。
- `dbviewer.newQuery` 生成的文档头部注释加了快捷键提示。

## 发布就绪度准备（面向插件市场）

**背景**：盖伦问「如何将本项目发布到插件市场」。先做了就绪度盘点与补齐。

**盘点结论**

- `publisher: "srdcloud"` 已是固定值，市场侧的 publisher ID 必须与之一致（建完不可改）。
- **缺 `icon`**：市场要求 PNG ≥128×128，项目里只有 `media/dbviewer.svg`（活动栏用），会被塞默认占位图。
- **无 `repository`**：这是 `--allow-missing-repository` 存在的原因，但不补的话市场页面没有仓库链接、README 里的相对链接无法解析。
- **git 仓库存在但 0 commit**（`.git` 有、`git rev-parse HEAD` 失败）——`vsce publish minor` 走 `npm version` 会在这一步失败。
- `docs/`（两张设计稿 PNG，164.6 KB）被打进 vsix，运行时用不到。

**本轮改动**

1. 新增 `scripts/build-icon.js`：**零依赖手写 PNG 编码器**（zlib.deflateSync + CRC32 chunk，与 `exporters.ts` 手写 XLSX 同一套取舍），SDF 判定形状 + 4 倍超采样降采样。产出 `media/icon.png`（256×256 RGBA，4.3 KB），配色取 DESIGN.md 的 `#1B1B1F` 底色 + `#11D080` 数据库圆柱。刻意用 Node 而非 Pillow，保持仓库单运行时。

**发布三条路（结论）**

## 需求迭代：连接节点右键打开 SQL Shell

**用户原话**：「右键点击链接可以选择打开sql shell。」→ 确认口径为「树视图连接节点右键 + Webview 交互式控制台」。

### 交付

| 文件 | 改动 |
|---|---|
| `package.json` | 命令 `dbviewer.openSqlShell`（`$(terminal)`）；`view/item/context` 加 `group: 1_query@0`、`when: viewItem =~ /^dbviewer\.connection/`；commandPalette 可见；activationEvents 追加 |
| `src/views/sqlShellPanel.ts`（新） | 面板实现，按 profileId 持有实例（`Map`），`hostPayload` 随连接信息下发 `metaHelp` |
| `media/sqlShell.css` / `sqlShell.js`（新） | 输出流 + 输入区，零依赖，全 DOM API 构建（禁止 innerHTML） |
| `src/commands/index.ts` | 注册命令；抽出 `confirmDestructive()`、`resolveProfileIdOrPrompt()`、`executeForShell()`、`openSqlShell()`、`SHELL_META_HELP` |
| `src/extension.ts` | `deactivate()` 里 `SqlShellPanel.disposeAll()` |

### 关键设计决策

1. **面板边界与 ResultPanel 完全一致**：扩展侧持输出缓冲 + 执行权，Webview 只输入/渲染。面板不接触驱动，`SqlShellHost.execute` 由命令层注入——否则只读拦截、超时、错误翻译全被绕过（沿用不变量 19）。
2. **执行结果用状态对象返回而非抛异常**：`{status:'ok'|'cancelled'|'error'}`。用户在二次确认里点「否」既不是成功也不是错误，靠异常区分会把它混进真实失败里。
3. **元命令在扩展侧处理**（`\?` `\l` `\dt` `\c` `\clear` `\q`，`quit`/`exit` 同义）：它们本质是快捷方式而非 SQL，丢给驱动只会得到语法错误。帮助文案单一来源在命令层 `SHELL_META_HELP`，前端不硬编码。
4. **单条输出最多推 200 行**（`MAX_SHELL_ROWS`）：扩展侧截断 + 前端二次限制。`rowCount > rows.length` 时前端提示去「新建查询」取完整结果。
5. **危险语句确认抽成 `confirmDestructive()`**：结果面板与 shell 共用同一份判定，避免两套逻辑漂移（漂移方向通常是"某个入口漏了确认"）。
6. **执行进度用 `ProgressLocation.Window`** 而非 Notification：shell 是连续交互，每次执行弹通知会一直抢焦点。
7. **`\c` 切库复用 `manager.connect(profileId, name)`** 的 databaseOverride 机制（会重建连接），通过闭包引用回写 `shell.updateHost()` 刷新标题栏。
8. **`\dt` 不出现驱动名分支**：按 `capabilities.schemas` 决定传 `database`（MySQL）还是空目标（PG），符合不变量 2。
9. 历史/草稿存 `vscode.setState()`，Webview 重建后 `ready → hydrate` 回放扩展侧输出缓冲，历史不丢。
10. 交互：Enter 或 Ctrl+Enter 执行、Shift+Enter 换行、↑↓ 翻历史（仅光标在首/末行时）、点单元格复制。

### 验证

- 冒烟测试 52 项不变；激活测试 51 → **64 项**（新增 13 项 SQL Shell 断言：菜单声明、面板创建、bootstrap、执行链路、错误/取消分支、元命令不误发驱动、hydrate 回放、清空、updateHost、面板复用与重建）。
