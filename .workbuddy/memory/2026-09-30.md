## 【多窗口表数据预览 · 0.6.0 未完待发】

需求（盖伦）：右键表「查看数据」的窗口同时只能看一张表；要支持多个表，且窗口名称就是对应的「库名.表名」。

**根因**：`views/resultPanel.ts` 的 `private static current` 是单例 —— 第二次「查看数据」只 `reveal` 已有窗口，把前一张表的结果冲掉。

**分层落点**：

| 层 | 改动 |
|---|---|
| 新增 `core/tableTargets.ts`（纯 Node，不认识 vscode） | `collectTableDataTargets()`（多选收集 / 去重）、`tableDataPanelKey()`（复用键）、`tableDataPanelTitle()`（「库.表」） |
| `views/resultPanel.ts` | 单例 → `Map<string, ResultPanel>` 按键注册表 + `disposeAll()` + `focused`（`onDidChangeViewState` 跟踪）；`show(uri, { key, title, preserveFocus })`；`dispose()` 由 async 改同步幂等 |
| `commands/index.ts` | `runSql()` 位置参数改选项对象（`profileId/target/title/panelKey/preserveFocus/editFallback/progressTitle/notifyError/refreshTree`）并返回 `RunSqlOutcome`；新增 `openTableData()`（多选批量）、`reportBatchFailures()`、`pickTableDataNodes()`；`showTableData` 接收第二参数（多选） |
| `media/result.js` | 头部新增 `headerLabel()`：`库.表 · 连接名`（多窗口并存时才分得清来源） |
| `extension.ts` | `deactivate` 改 `ResultPanel.disposeAll()` |

**关键取舍（写进 MEMORY.md 第 28 条）**：

1. 复用键含 `profileId`：两个连接里的同名表不能挤进同一个窗口。
2. **允许跨连接多选**（与备份相反：备份一次只出一个文件所以拒绝跨连接）。
3. **顺序读取不并发**：驱动是单连接（`mysql.createConnection` / `new Client`），并发只会让排队语义、超时判定、错误归属变复杂。
4. 批量进度只有一条（`progressTitle: null` 让 `runSql` 不自己弹），报错静默（`notifyError: false`），由 `openTableData` 汇总一条 + 明细进输出通道 —— 20 张表弹 20 个错误提示等于不可用。
5. 窗口标题在 `show()` 时一次定终身；面板内改 SQL 重跑留在原窗口、标签不变。
6. `.sql` 入口仍用缺省键（共用「查询结果」窗口），所以表数据窗口不会被编辑器查询顶掉 —— 这是「不再互相覆盖」的另一半。

**测试**：`npm test` 全绿 —— 冒烟 **89 项**（原 83，新增第 16 节「表数据预览：多选目标收集」6 项）、激活 **72 项**（原 66：新增多窗口 5 项 + 多选命令空/无效参 1 项）。mock 面板补了 `active` / `onDidChangeViewState` / `reveal` 的 `viewColumn` 记录 / `setActive()`。

**踩到的坑**：

| # | 问题 | 修法 |
|---|---|---|
| 1 | 多窗口用例假失败（`1 !== 2`）：上一条用例的复用键还在全局注册表里，同键 `show` 直接复用 → 只新建了 1 个窗口 | 每个用例开头 `ResultPanel.disposeAll()`：复用键是全局状态，用例之间必须互不依赖 |
| 2 | `tableDataPanelTitle` 若沿用旧写法 `${schema ?? database ?? ''}.${table}`，两段都缺时会产出 `.users` | 无限定名时只给表名 |
| 3 | mock 面板原本没有 `onDidChangeViewState`，直接调用会 TypeError | 补进 mock（与上轮 `withProgress` 缺 token 同类问题：mock 比真实 API 少一点，测试就会以奇怪的方式失败或假通过） |

**未做**：不改版本号（仍 0.6.0）、不发布 —— 0.5.0 还在 Marketplace `Verifying`，重传会清零验证计时。仅打包到 `.tmp-vsix/` 供本机安装验证。

## 【右键编辑表结构 / 数据库属性 · 0.6.0 未完待发】

需求（盖伦）：右键点表或数据库时支持编辑该对象的属性，例如表可以改表结构。

**分层落点**（一条主线：Webview 只回传目标状态，扩展侧重算差异、驱动生成并执行语句）：

| 层 | 改动 |
|---|---|
| `core/types.ts` | `DriverCapabilities` 加 `editTableStructure` / `editDatabaseProperties`；新增 `EditableProperty`、`TableColumnDefinition`、`TableStructure`、`DatabaseObjectTarget`、`DatabaseProperties`、`TableChangeRequest`、`DatabaseChangeRequest`、`ObjectChangePlan/Result` 与六个可选驱动方法 |
| `core/objectEditor.ts`（新，纯 Node） | 差异计算（`diffTableColumns` / `diffPrimaryKey` / `diffProperties` / `summarizeColumnsDiff`）+ 提交前校验（`validateColumnDefinitions` / `validateObjectName`）+ 文本归一（`normalizeTypeText` / `normalizeDefaultText`） |
| `drivers/mysqlStructure.ts`、`drivers/pgStructure.ts`（新，纯函数） | 差异 → DDL。**刻意与驱动实现分开**：不 require SDK，冒烟测试直接断言生成的语句（写错一条 ALTER 是要丢数据的） |
| `drivers/mysql.ts` / `pg.ts` | `describeTable` / `describeDatabaseProperties`（读现状）+ `plan*Change`（委托纯函数）+ `apply*Change`（执行）；MySQL 逐条执行，PG 包事务 |
| `drivers/sidecarProxy.ts` / `sidecar/host.ts` | 六个新 RPC 转发 |
| `views/objectEditorPanel.ts`、`media/objectEditor.js`、`media/objectEditor.css`（新） | 单实例面板，模型随 bootstrap 下发（避免先空一屏）；属性控件 + 列定义表格 + 语句预览 + 变更摘要 + 风险提示 + 结果区 |
| `commands/index.ts` | `dbviewer.editTableStructure` / `dbviewer.editDatabaseProperties` + 共享的 `openObjectEditor()`（读现状 → 生成模型 → 打开面板；apply 前先 `planIsEmpty` 拦空计划，再复用 `confirmDestructive()` 二次确认，成功后重读模型并刷新树） |
| `package.json` / `README.md` / `CHANGELOG.md` | 两条命令 + 表 / 库 / schema 节点右键菜单（`3_modify@0`）、命令面板隐藏；文档与更新日志 |

**关键取舍（写进 MEMORY.md 第 29 条）**：

1. **预览与应用共用同一个 `plan()`**，且 `plan` 每次都让驱动重读现状 —— 面板里的「原始值」只用于渲染，绝不当成生成 DDL 的依据。
2. **重命名的唯一凭据是 `originalName`**：改名走 `CHANGE COLUMN` / `RENAME COLUMN`，而不是「删旧增新」（后者会丢数据）。`properties.name` 是保留的重命名键。
3. **`allowReorder` / `allowAutoIncrement` 是驱动给界面的数据**：PG 不显示调序按钮，也不给既有列的自增开关（不支持的驱动只回传原值，避免每次都报「自增被忽略」）。
4. 能力位 + 实现双重检查后才开面板（能力位是驱动自己声明的，第三方驱动可能声明了却没实现）。
5. 一条命令对一个对象类别：菜单里要给出明确名字，合并成「编辑属性」再猜类型只能写成含糊的「编辑…」。
6. 结构变更走 `driver.execute()`，只读连接（`EREADONLY`）与超时因此自动生效。

**测试**：`npm test` 全绿 —— 冒烟 **126 项**（原 89，新增第 17/18/19 节共 37 项）、激活 **88 项**（原 72，新增「对象属性编辑器」16 项）；另有 `npm run test:live` 真库联调 **24 项**（见下）。

**真库联调（本机 MySQL 8.0.46）—— 这轮最值回票价的一步**：纯函数测试只能断言「生成的语句长什么样」，收不收得下只有服务端知道。为此新增 `scripts/live-mysql-test.js`（`npm run test:live`，凭据走环境变量，不进 `npm test` 门禁）：自建 `__dbviewer_probe_<时间戳>` 库，跑「读结构 → 生成计划 → 执行 → 复读校验 → 失败路径 → 库属性 → 删库」，用的是**编译产物里的真实驱动**。它抓出三个纯逻辑测试永远测不到的 bug：

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | `ALTER DATABASE` 报语法错误，位置指向逗号 | MySQL 的 `ALTER DATABASE` **不接受逗号分隔的多个选项**（`CHARACTER SET = a, COLLATE = b` 直接失败），只有 `ALTER TABLE` 才是逗号分隔 | 库属性子句改成空格相连；冒烟断言里加「不得出现逗号」 |
| 2 | `MODIFY note text DEFAULT ''` 被拒：`BLOB, TEXT, GEOMETRY or JSON column can't have a default value` | MySQL 8.0.13 起这几类列**只能**写表达式默认值 `DEFAULT (…)`；且读回来的是转义过、带字符集引导符的形式（`_utf8mb4\'hello\'`，SHOW CREATE 里才显示成 `_utf8mb4'hello'`），原样写回同样报语法错误 | `renderMysqlDefault` 加一路：表达式默认值先**反转义**（单次左到右扫描，避免 `\\'` 被吃两层）再补括号；TEXT/BLOB/JSON/GEOMETRY 无论用户填什么都走 `DEFAULT ('…')`；数字类型上手打的裸表达式（`3 * 7`）也补括号 |
| 3 | 只是给时间戳列加了个注释，`ON UPDATE CURRENT_TIMESTAMP` **被静默抹掉**（服务端一个字都不报，表行为已经变了） | 该子句只存在于 `information_schema.COLUMNS.EXTRA`（`DEFAULT_GENERATED on update CURRENT_TIMESTAMP(3)`），不属于类型 / 默认值 / 可空任何一项，于是改写列定义时没有任何人带上它 | 列定义新增 `extraClauses` 原样往返：驱动从 EXTRA 提取 → 界面用隐藏域带回并在默认值旁标注 → 渲染时接在 DEFAULT 之后；请求里缺失时按 `originalName` 从现状继承（第三方调用也不会静默丢） |

**这轮顺带证明的事**（都在真库上跑通并复读一致）：`int(10) unsigned zerofill` / `enum` / `set` / `bit(1)` / `binary(4)` / `timestamp(3)` 的类型与默认值保真；复合主键增删；列改名 + 调序 + 增删列合成一条 `ALTER`；`RENAME TABLE` 排在最后；`ENGINE` 切换；空串默认值与「无默认值」的区分。失败路径也是实测出来的：造「第 1 条 ALTER 成功、第 2 条 RENAME 撞上同名表」的场景，确实回报「第 2 条语句执行失败（共 2 条，前 1 条已生效）」，且第 1 条真的已落库 —— 这正是 MySQL 无 DDL 事务的语义。

**踩到的坑**（面板 / 测试侧的）：

| # | 问题 | 修法 |
|---|---|---|
| 1 | 把 `appendLimit` 的函数体误删（插入新 helper 时切错了行区间），编译才发现 | 从 `git diff` 比对恢复；行区间插入前先确认边界 |
| 2 | MySQL 先 `DROP COLUMN` 后 `DROP PRIMARY KEY` 会报「主键不存在」（删主键列时 MySQL 已连带丢掉主键） | 固化子句顺序，并写成冒烟断言（PG 同理：`DROP CONSTRAINT` 必须在 `DROP COLUMN` 之前） |
| 3 | 断言 `viewItem == dbviewer.view` 的 when 里不能出现 `view` 字样 —— `view == dbviewer.connections` 里就有 | 断言写成匹配具体 `viewItem == dbviewer.table` |
| 4 | 面板用例连挂 6 条：前一条用例 `disposeAll()` + 重新 `open()` 后，断言还在往**旧面板**发消息（`disposed` 后面板静默丢弃 post） | 用例统一用 `liveView()`（取 `webviewPanels` 最后一个） |
| 5 | `definitions` 被同文件上方的 `const definitions = require('drivers/definitions.js')` 遮蔽 | 用 `definitions.BUILTIN_DEFINITIONS` |
| 6 | 字符集 / 引擎名用反引号包出来（`` CHARACTER SET = `utf8mb4` ``）不像人手写的 DDL | 加 `optionValue()`：纯 `[A-Za-z0-9_]+` 裸输出，其余才加引号（保留防注入） |
| 7 | 手写新增的异步用例忘了 `await checkAsync(...)`（脚本头部注释明确警告过） | 批量补 `await` 后再跑，避免「假通过」 |
| 8 | 联调脚本自己写错：把列改名后还按旧名 `byName('name')` 取引用，`undefined.comment` 直接崩 | 改名之前先把要用到的列引用全部抓出来；这也是「断言失败先怀疑脚本」的典型 |
| 9 | 想在联调里造服务端报错，却被**自己的客户端校验**先拦下（列名重复） | 换成「客户端校验过得去、服务端必失败」的场景（改名撞同名表），顺带把「第 N 条已生效」也一起验了 |
